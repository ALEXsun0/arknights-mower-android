# APK 更新默认应用内置组件

0.2.6 起，每次覆盖安装 APK 后，首次启动服务默认使用此 APK 内置的 Mower、MAA 核心与资源。识别依据为 APK versionCode 和系统 lastUpdateTime；同版本重装也会触发。排班、Mower 配置、原生软件设置、局域网参数与 MAA config/config.json 保留。

只在同一个 APK 内停止并重新启动服务时，保留用户后续导入或在线热更新的组件。MAA 的旧 cache/resource 不带入新包，避免旧热更新资源覆盖内置资源。已有 Python 兼容接口热更新仍由其独立更新器管理。

## 切换与恢复

- Python 环境按安装记录重新展开，沿用原有暂存、校验与启动失败回退；更新并未完成就中断时允许重试。
- Mower 热更新程序目录原先优先于包内源码。现在新 APK 首次启动明确选择内置源码，保留原程序作为回退，认证的启动就绪接口通过后才清理。回退不重复触发同一 APK 的重置。
- MAA 内置压缩包先校验再替换；安装记录最后提交，半途退出时下次重试。Python 再切换实际使用目录，保留配置并将旧目录放入 maa.old。第一次 MAA 任务正常完成后复用现有清理机制删除旧核心/资源备份。
- 替换目录后、删除待处理标记前退出的情况可恢复，不会把新目录反复备份并覆盖真正的旧备份。
