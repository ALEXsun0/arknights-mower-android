# 原生诊断导出与清理

软件设置 → 诊断日志打开独立原生页面，不需要启动 Python 服务、游戏或排班。

- 默认最近 2 小时，可选最近 30 分钟、2 小时、24 小时，或分别选择开始、结束日期及时间。日志和截图使用同一时段。
- 用户决定是否包含截图；默认包含时段内全部现存截图。预览显示可用数量、占用、本次选中数量及预计包体积。
- 可选关键截图模式，优先订单截图、错误前后两分钟；其余按时段采样，最多 128 MiB / 512 张，并明确显示省略数量。
- 包含原始截图、日志、系统诊断及 manifest.json。清单记录实际收入的图片、拍摄时间、字节数、缺失引用和主动省略数量。截图不会经过日志脱敏处理，日志中 Token 会脱敏。
- 可以调用系统分享，包括 LocalSend / QQ，或使用系统文件选择器保存到本地后再传输。
- 页面底部操作固定在可见区域，长日志放入独立滚动区域，避免竖屏时导出按钮被挤到屏幕外。

## 保留与清理

导出不修改截图保留设置，不删除截图源文件。24 小时设置继续由 Mower 管理；原有重要分类保留最近 100 张的规则不变，因此它不是对所有图片一刀切的绝对 24 小时删除。未写盘或已清理的画面不能恢复。

清理入口可分别选择运行日志（所有时段）与已生成的诊断包，显示占用后再次确认。运行日志保留文件并清空内容，保证已经打开的追加写入句柄继续有效；不触碰截图、排班、配置或系统日志。删除诊断 ZIP 会一并删除其中的截图副本，但不影响截图原文件。

诊断 ZIP 使用独立文件名和临时文件写入，完成后才提供给分享程序，失败或取消时清理临时文件。应用缓存中超过 24 小时的旧诊断 ZIP 在下次导出时清理；用户另存的副本不自动删除。

## 边界

控制台最多读取末尾 4 MiB；最近四个 Mower 日志各最多 2 MiB。读取上限可能使所选时段更早的日志缺失，文件头及 README 会说明。系统诊断反映最近状态，不严格限制到所选时段。估算包体积按未压缩日志与图片字节数加余量显示；完整截图模式需要相应可用空间。

为避免 Android Deflater 在条目间切换压缩级别导致的归档损坏，整个 ZIP 使用固定的快速压缩级别。图片以流方式复制，不将全部图片放入内存。

## 验证

- Android 单元测试 173 项、Release Lint 通过。
- 模拟器导出含图片 ZIP：逐条解压及 CRC 校验通过，图片与原文件逐字节相同，时间范围外的测试图片未收入。
- 模拟器导出仅日志 ZIP：没有图片条目，清单明确标注未请求截图。
- 系统文件保存成功；竖屏预览和固定底部按钮验证通过。
- 模拟器本身禁止自动旋转，横屏未计入实测结论。
- 验证记录：`artifacts/diagnostics-export-test/validation.json`。
- 本地发行签名 APK：`artifacts/diagnostics-refactor/mower-android-arm64.apk`，版本沿用 0.2.6 / 26。此包尚未安装到实机，也未替换已公开的 v0.2.6 发行附件。
